跨版本兼容：构建支持 Vue 2 和 Vue 3 的通用组件

yanyue404
发布于 2024-08-30
约 22 分钟

前言

在现代前端开发中，随着框架版本的升级，如何有效管理和维护组件库的兼容性已成为高级前端工程师的必备技能。本文将深入探讨如何构建一个同时兼容 Vue 2 和 Vue 3 的通用组件，并讨论在此过程中需要注意的关键点。

Vue 3 渲染函数的重大变化

Vue 3 引入了多个针对渲染函数 API 的改动，旨在提高性能和一致性。这些更改虽然提升了框架的灵活性和易用性，但也给兼容性带来了挑战。以下是 Vue 3 渲染函数的主要变化概述：

渲染函数参数的变化

在 Vue 2 中，render 函数会自动接收 h 函数 (即 createElement) 作为参数，而在 Vue 3 中，h 函数已被移至全局导入。这种变化要求开发者在编写跨版本兼容的代码时格外注意。

Vue 2 示例：

// Vue 2 渲染函数示例
export default {
  render(h) {
    return h('div')
  }
}

Vue 3 示例：

// Vue 3 渲染函数示例
import { h } from 'vue'

export default {
  render() {
    return h('div')
  }
}

VNode Prop 的结构扁平化

Vue 3 对 VNode Prop 的结构进行了扁平化处理，从而简化了数据结构。这种改动减少了开发者在处理 VNode 时的认知负担，但同样需要对旧代码进行改造。

Vue 2 示例：

// 2.x VNode prop 示例
{
    staticClass: 'button',
    class: { 'is-outlined': isOutlined },
    staticStyle: { color: '#34495E' },
    style: { backgroundColor: buttonColor },
    attrs: { id: 'submit' },
    domProps: { innerHTML: '' },
    on: { click: submitForm },
    key: 'submit-button'
}

Vue 3 示例：

// 3.x VNode prop 示例
{
    class: ['button', { 'is-outlined': isOutlined }],
    style: [{ color: '#34495E' }, { backgroundColor: buttonColor }],
    id: 'submit',
    innerHTML: '',
    onClick: submitForm,
    key: 'submit-button'
}

组件注册方式的调整

Vue 3 在组件注册方面引入了 resolveComponent，要求显式导入组件并进行注册，这与 Vue 2 中可以通过字符串直接引用组件的方式形成了鲜明对比。

Vue 2 示例：

// Vue 2 组件注册示例
Vue.component('button-counter', {
  data() {
    return {
      count: 0
    }
  },
  template: `<button @click="count++"> Clicked {{ count }} times. </button>`
})

export default {
  render(h) {
    return h('button-counter')
  }
}

Vue 3 示例：

// Vue 3 组件注册示例， resolveComponent 用于按名称手动解析已注册的组件。
// 如果你可以直接引入组件就不需使用此方法。比如用 defineComponent、defineAsyncComponent
import { h, resolveComponent } from 'vue'

export default {
  setup() {
    const ButtonCounter = resolveComponent('button-counter')
    return () => h(ButtonCounter)
  }
}

创建跨 Vue 版本兼容的渲染方法

在构建通用组件时，最关键的步骤之一是根据不同的 Vue 环境来初始化渲染组件。下面的代码展示了如何为 Vue 2 和 Vue 3 创建一个基础的渲染方法，并提供了一个进阶版本，利用 vue-demi 库进一步提升兼容性和代码的可维护性。

基础实现

基础实现的目标是通过一个统一的接口，确保在 Vue 2 和 Vue 3 环境中都能正常渲染组件。

let createVmFn
export function setCreateVmFn(fn) {
  createVmFn = fn
}
export function mount(component, opt, el) {
  if (!component) {
    console.warn('请传入正确的组件')
  }
  if (!el) {
    el = document.createElement('div')
    document.body.appendChild(el)
  }
  if (!createVmFn) {
    console.warn('使用 mount 方法前，请确保加载入口文件')
    return
  }
  return createVmFn(component, opt, el)
}

入口文件示例

针对 Vue 2 和 Vue 3 分别实现了不同的入口函数，用以初始化组件的挂载过程。

// Vue 2 入口文件
import Vue from 'vue'
setCreateVmFn(
  (component, opt, el) =>
    new Vue({
      el,
      render(h) {
        return h(component, opt)
      }
    })

// Vue 3 入口文件
import { createApp, h } from 'vue'
setCreateVmFn((component, opt, el) => {
  const app = createApp({
    render() {
      return h(component, opt)
    }
  })
  app.mount(el)
  return app
})

进阶实现：利用 vue-demi 进行兼容性处理

https://github.com/yanyue404/vue-demi/blob/main/examples/

为了进一步提升跨版本的兼容性，我们可以借助 vue-demi 库，它提供了 Vue 2 和 Vue 3 之间的一层适配层，使得同一份代码在两个版本中均可运行。下面的代码展示了如何使用 vue-demi 实现这一目标。

import { isVue2, Vue, createApp, h as hDemi } from 'vue-demi'

function adaptOnsV3(ons) {
  if (!ons) return null
  return Object.entries(ons).reduce((ret, [key, handler]) => {
    key = key.charAt(0).toUpperCase() + key.slice(1)
    key = `on${key}`
    return { ...ret, [key]: handler }
  }, {})
}

// 使用 Vue2 语法编写
export function h(type, options, children) {
  if (isVue2) return hDemi(type, options, children)

  const { props, domProps, on, ...extraOptions } = options

  const ons = adaptOnsV3(on)
  const params = { ...extraOptions, ...props, ...domProps, ...ons }
  return hDemi(type, params, children)
}

export function mount(component, opt, el) {
  if (!component) {
    console.warn('请传入正确的组件')
  }
  if (!el) {
    el = document.createElement('div')
    document.body.appendChild(el)
  }

  if (isVue2) {
    return new Vue({
      el,
      render(h) {
        return h(component, opt)
      }
    })
  } else {
    const app = createApp({
      render() {
        return h(component, opt)
      }
    })
    app.mount(el)
  }
}

另一种采用 Vue3 的 props 写法兼容适配方案

import { isVue2 } from 'vue-demi'
const attrsNames = ['src']

export function transformVNodeProps(props) {
  if (!isVue2) {
    return props
  }

  // 创建需转移的结构
  const on = {}
  const attrs = {}
  const domProps = {}

  // 处理 class
  let staticClass = '',
    classNames = {}
  if (props.class) {
    staticClass = props.class.filter(v => typeof v === 'string').join(' ') || ''

    props.class
      .filter(v => typeof v === 'object')
      .forEach(o => {
        classNames = Object.assign(classNames, o)
      })
  }
  // 处理 style
  const staticStyle = props.style ? Object.assign({}, ...props.style) : {}

  // 处理 onClick 事件
  Object.keys(props).forEach(key => {
    if (key.startsWith('on') && key.length > 2) {
      const eventName = key[2].toLowerCase() + key.substring(3)
      on[eventName] = props[key]
      delete props[key]
    }
  })

  // 处理 attrs 和 domProps
  Object.keys(props).forEach(key => {
    if (key === 'innerHTML') {
      domProps.innerHTML = props[key]
      delete props[key]
    } else if (['id', 'src'].includes(key)) {
      attrs[key] = props[key]
      delete props[key]
    }
  })

  // 组装最终结构
  return {
    staticClass,
    class: classNames,
    staticStyle,
    attrs,
    domProps,
    on,
    key: props.key
  }
}

我需要在 vue3、vue2 不同的项目中使用同一个 dialog 组件，需要按不同的 props 展示，同时需要异步等待得到弹窗后的最终状态是 cancel 和 confirm，同时需要在不同的环境完美兼容，帮我思考一下实现，多种方法，最佳方法

在 Vue 2 和 Vue 3 项目中复用同一个 Dialog 组件，并实现根据不同 props 展示内容、异步等待弹窗状态（cancel 或 confirm）、以及跨环境兼容，是一个常见的组件设计需求。下面我会分析多种实现方法，逐步优化，最终给出推荐的最佳方案。

需求分析

  1. 跨 Vue 2 和 Vue 3 兼容
    • Vue 2 使用 Options API，Vue 3 支持 Composition API 和 <script setup>。
    • 需要处理 API 差异（如 v-model 语法、props 定义等）。
  2. 动态 Props
    • 根据传入的 props（如标题、内容、按钮文本等）动态渲染弹窗。
  3. 异步状态返回
    • 调用方需要等待用户操作（confirm 或 cancel）的结果，返回 Promise。
  4. 复用性
    • 组件代码尽量统一，避免为 Vue 2 和 Vue 3 写两套实现。

方法一：基于组件 + 事件监听

思路

  • 编写一个 Dialog 组件，接受 props 控制显示内容。
  • 通过 $emit 触发 confirm 或 cancel 事件，调用方监听事件获取结果。
  • 使用 visible 控制显示/隐藏（Vue 2 和 Vue 3 都支持）。

实现

<!-- Dialog.vue -->
<template>
  <div class="dialog" v-if="visible">
    <h3>{{ title }}</h3>
    <p>{{ content }}</p>
    <button @click="handleConfirm">{{ confirmText }}</button>
    <button @click="handleCancel">{{ cancelText }}</button>
  </div>
</template>

<script>
export default {
  name: 'Dialog',
  props: {
    visible: { type: Boolean, default: false },
    title: { type: String, default: '标题' },
    content: { type: String, default: '内容' },
    confirmText: { type: String, default: '确认' },
    cancelText: { type: String, default: '取消' }
  },
  methods: {
    handleConfirm() {
      this.$emit('confirm')
      this.$emit('update:visible', false) // 关闭弹窗
    },
    handleCancel() {
      this.$emit('cancel')
      this.$emit('update:visible', false) // 关闭弹窗
    }
  }
}
</script>

this.$once('confirm', () => resolve('confirm')) 的详细讲解

什么是 this.$once？

  • 在 Vue 2 中，Vue 实例提供了事件系统，包括 $on、$once、$emit 和 $off 方法。
  • $once(eventName, callback) 是 Vue 提供的一个方法，用于监听某个事件，但它只会在事件触发一次后执行回调，然后自动移除监听。
  • 相比 $on（持续监听），$once 更适合“一次性事件”的场景，比如我们这里只需要监听用户的一次确认或取消操作。

代码中的作用

在 showDialogAsync 方法中：

showDialogAsync() {
  return new Promise((resolve) => {
    this.$once('confirm', () => resolve('confirm'));
    this.$once('cancel', () => resolve('cancel'));
  });
}

  1. 创建 Promise

    • new Promise((resolve) => {...}) 创建一个 Promise，resolve 是用来解析 Promise 的函数。
    • 这个 Promise 会返回给调用方（openDialog 中的 await），等待用户操作的结果。

  2. 监听事件

    • this.$once('confirm', () => resolve('confirm')) 表示：
      • 监听 confirm 事件，当 Dialog 组件通过 this.$emit('confirm') 触发该事件时，执行回调。
      • 回调中调用 resolve('confirm')，将 'confirm' 作为 Promise 的结果返回。
      • 因为是 $once，事件触发后，监听自动移除，不会重复执行。
    • 同理，this.$once('cancel', () => resolve('cancel')) 监听 cancel 事件。

  3. 事件触发流程

    • 用户点击“确认”按钮，Dialog 组件触发 this.$emit('confirm')。
    • App.vue 的 onConfirm 方法接收到事件，再通过 this.$emit('confirm') 冒泡到 showDialogAsync。
    • $once('confirm', ...) 的回调触发，resolve('confirm') 执行，Promise 完成。

为什么用 $once 而不是 $on？

  • 如果用 $on，事件监听不会自动移除。如果用户多次打开弹窗，可能会导致多次监听堆积，回调被重复调用。
  • $once 确保每次弹窗只监听一次，触发后清理，避免内存泄漏或逻辑错误。

为什么需要 this.$emit 冒泡？

  • 在 App.vue 中，Dialog 组件触发的事件（confirm 或 cancel）需要传递到 showDialogAsync 的监听。
  • 因为 showDialogAsync 是定义在 App.vue 中的方法，它监听的是 App 实例上的事件，而不是直接监听 Dialog 组件。
  • 因此，onConfirm 和 onCancel 方法通过 this.$emit 将事件“冒泡”到 App 实例。

运行完整示例的步骤

  1. 创建一个 Vue 2 项目： 
    npm install -g @vue/cli
vue create my-project --default
cd my-project
  2. 将上述 Dialog.vue、App.vue 和 main.js 替换到项目对应位置。
  3. 运行项目： 
    npm run serve
  4. 打开浏览器，点击按钮测试。

优点与注意事项

优点

  • 简单明了：基于 Vue 2 原生事件系统，无需额外依赖。
  • 异步支持：通过 Promise 实现异步等待，符合需求。
  • 复用性：Dialog 组件可通过不同 props 在多个地方使用。

注意事项

  • 事件清理：使用 $once 已避免手动清理，但若改为 $on，需要在弹窗关闭后用 $off 移除监听。
  • Vue 2 限制：v-model 在 Vue 2 中需要用 :visible.sync，Vue 3 则直接用 v-model。
  • 动态挂载替代：如果不需要组件在模板中声明，可以参考前文“方法二”动态挂载的方式。

优点

  • 简单直观，易于理解。
  • Vue 2 和 Vue 3 兼容性较好（只需调整 v-model 语法）。

缺点

  • 异步操作需要手动封装 Promise，调用方代码较繁琐。
  • 组件状态（visible）由父组件控制，复用性稍弱。

方法二：基于 Promise + 动态组件挂载

思路

  • 将 Dialog 封装成一个工具函数，通过动态创建组件实例并挂载到 DOM。
  • 函数返回 Promise，直接解析用户操作结果。
  • 在 Vue 2 和 Vue 3 中使用统一的调用方式。

实现

// dialog.js
import { createApp, h, getCurrentInstance } from 'vue'
import DialogVue from './Dialog.vue'

// Vue 3 实现
function createDialog(options = {}) {
  const { title = '标题', content = '内容', confirmText = '确认', cancelText = '取消' } = options

  return new Promise(resolve => {
    const div = document.createElement('div')
    document.body.appendChild(div)

    const app = createApp({
      render() {
        return h(DialogVue, {
          visible: true,
          title,
          content,
          confirmText,
          cancelText,
          'onUpdate:visible': val => {
            if (!val) {
              app.unmount()
              div.remove()
            }
          },
          onConfirm: () => resolve('confirm'),
          onCancel: () => resolve('cancel')
        })
      }
    })

    app.mount(div)
  })
}

// Vue 2 兼容版本（需调整）
import Vue from 'vue'
function createDialogVue2(options = {}) {
  const { title = '标题', content = '内容', confirmText = '确认', cancelText = '取消' } = options

  return new Promise(resolve => {
    const div = document.createElement('div')
    document.body.appendChild(div)

    const DialogConstructor = Vue.extend(DialogVue)
    const instance = new DialogConstructor({
      propsData: {
        visible: true,
        title,
        content,
        confirmText,
        cancelText
      }
    })

    instance.$on('confirm', () => {
      resolve('confirm')
      instance.$destroy()
      div.remove()
    })
    instance.$on('cancel', () => {
      resolve('cancel')
      instance.$destroy()
      div.remove()
    })

    instance.$mount(div)
  })
}

export default process.env.VUE_VERSION === '2' ? createDialogVue2 : createDialog

优点

  • 调用方无需管理 visible 状态，组件自销毁。
  • 异步操作简洁，直接返回 Promise。
  • 跨 Vue 2 和 Vue 3 兼容（通过条件导出）。

缺点

  • 需要为 Vue 2 和 Vue 3 维护两套挂载逻辑。
  • 动态挂载可能增加调试复杂性。

方法三：最佳方案 - 单文件组件 + 插件式封装

思路

  • 使用单文件组件（SFC）编写 Dialog，同时支持 Vue 2 和 Vue 3。
  • 封装为插件，提供全局方法（如 this.$dialog），通过 Promise 返回结果。
  • 使用 vue-demi 解决 Vue 2 和 Vue 3 的兼容性问题。

实现

  1. 安装 vue-demi

    npm install vue-demi

  2. Dialog 组件

<!-- Dialog.vue -->
<template>
  <div class="dialog" v-if="visible">
    <h3>{{ title }}</h3>
    <p>{{ content }}</p>
    <button @click="handleConfirm">{{ confirmText }}</button>
    <button @click="handleCancel">{{ cancelText }}</button>
  </div>
</template>

<script>
import { defineComponent } from 'vue-demi'

export default defineComponent({
  name: 'Dialog',
  props: {
    visible: { type: Boolean, default: false },
    title: { type: String, default: '标题' },
    content: { type: String, default: '内容' },
    confirmText: { type: String, default: '确认' },
    cancelText: { type: String, default: '取消' }
  },
  emits: ['update:visible', 'confirm', 'cancel'],
  setup(props, { emit }) {
    const handleConfirm = () => {
      emit('confirm')
      emit('update:visible', false)
    }
    const handleCancel = () => {
      emit('cancel')
      emit('update:visible', false)
    }
    return { handleConfirm, handleCancel }
  }
})
</script>
  1. 插件封装
// dialog-plugin.js
import { isVue2, Vue2 } from 'vue-demi'
import Dialog from './Dialog.vue'

const DialogPlugin = {
  install(Vue) {
    const DialogConstructor = isVue2 ? Vue2.extend(Dialog) : Vue

    Vue.prototype.$dialog = function(options = {}) {
      return new Promise(resolve => {
        const div = document.createElement('div')
        document.body.appendChild(div)

        const instance = isVue2
          ? new DialogConstructor({
              propsData: { ...options, visible: true }
            })
          : new (Vue.createApp({
              render: () =>
                h(Dialog, {
                  ...options,
                  visible: true,
                  'onUpdate:visible': val => {
                    if (!val) {
                      instance.unmount?.() || instance.$destroy()
                      div.remove()
                    }
                  },
                  onConfirm: () => resolve('confirm'),
                  onCancel: () => resolve('cancel')
                })
            }))()

        if (isVue2) {
          instance.$on('confirm', () => resolve('confirm'))
          instance.$on('cancel', () => resolve('cancel'))
          instance.$mount(div)
        } else {
          instance.mount(div)
        }
      })
    }
  }
}

export default DialogPlugin
  1. 安装插件
// main.js (Vue 2 或 Vue 3)
import Vue from 'vue' // 或 import { createApp } from 'vue'
import DialogPlugin from './dialog-plugin'

if (Vue.prototype) {
  Vue.use(DialogPlugin) // Vue 2
} else {
  const app = createApp(App)
  app.use(DialogPlugin) // Vue 3
  app.mount('#app')
}
  1. 使用

  </div>

    }
  }
}
</script>

优点

  • 完美兼容：通过 vue-demi 抹平 Vue 2 和 Vue 3 差异。
  • 简洁调用：全局方法 $dialog，无需手动管理组件。
  • 异步优雅：直接返回 Promise，结果清晰。
  • 高复用性：一个组件 + 插件即可在多个项目中使用。

缺点

  • 需要额外依赖 vue-demi，但这是轻量且成熟的解决方案。

最佳方法推荐

方法三（单文件组件 + 插件式封装） 是最佳方案，原因如下：

  1. 跨版本兼容性：借助 vue-demi，无需为 Vue 2 和 Vue 3 写两套代码。
  2. 使用简便：全局方法调用，异步结果通过 Promise 返回，符合现代开发习惯。
  3. 可维护性强：组件逻辑集中在 Dialog.vue，插件逻辑独立，易于扩展（如添加更多功能）。
  4. 动态挂载：无需父组件管理状态，组件自销毁，减少内存泄漏风险。

扩展建议

  • 添加自定义内容支持：通过 slots 或 render 函数传入自定义模板。
  • 支持更多状态：如 loading 状态，防止重复点击。
  • 类型安全：结合 TypeScript 定义 options 类型。

希望这个方案能满足你的需求！如果有具体细节需要调整，可以进一步讨论。

帮我参考开源项目，有没有其他更好的实现思路或封装

开源项目参考

1. Vuetify 的 v-dialog

  • 特点：
    • Vuetify 是 Vue 的 Material Design UI 框架，其 v-dialog 组件支持 v-model 控制显隐，提供丰富的 props（如 width、persistent）和 slots（如 activator、default）。
    • 支持 Vue 2 和 Vue 3（通过不同版本）。
  • 实现思路：
    • 组件内部通过 v-model 双向绑定控制显隐。
    • 使用 transition 实现动画效果。
    • 通过 slot 提供内容自定义。
  • 代码片段（Vue 2 示例）： 
    <template>
  <v-dialog v-model="dialog" max-width="500px">
    <v-card>
      <v-card-title>{{ title }}</v-card-title>
      <v-card-text>{{ content }}</v-card-text>
      <v-card-actions>
        <v-btn @click="dialog = false">{{ cancelText }}</v-btn>
        <v-btn @click="$emit('confirm')">{{ confirmText }}</v-btn>
      </v-card-actions>
    </v-card>
  </v-dialog>
</template>
<script>
export default {
  data: () => ({ dialog: false }),
  props: ['title', 'content', 'confirmText', 'cancelText']
}
</script>
  • 优点：
    • 开箱即用，样式美观。
    • 支持动态 props 和事件。
  • 缺点：
    • 依赖 Vuetify 框架，体积较大。
    • 异步状态需手动封装 Promise。

2. Element Plus 的 el-dialog（Vue 3）

  • 特点：
    • Element Plus 是 Vue 3 的 UI 框架，el-dialog 支持 v-model 和丰富的配置选项（如 before-close）。
    • 支持动态内容和事件监听。
  • 实现思路：
    • 通过 v-model:visible 控制显隐。
    • 提供 before-close 钩子处理关闭逻辑。
  • 代码片段： 
    <template>
  <el-dialog v-model="dialogVisible" :title="title" width="500px">

    </template>
  </el-dialog>
</template>
<script>
export default {
  data: () => ({ dialogVisible: false }),
  props: ['title', 'content', 'confirmText', 'cancelText']
}
</script>
  • 优点：
    • 配置灵活，支持 Vue 3。
    • 内置懒加载（内容首次打开才渲染）。
  • 缺点：
    • 不支持 Vue 2。
    • 异步封装仍需手动处理。

3. vue-final-modal

  • 特点：

    • 一个轻量、独立、可堆叠的模态框组件，支持 Vue 2 和 Vue 3。
    • 提供动态挂载和 Promise 式 API。

  • 实现思路：

    • 通过 Vue.extend（Vue 2）或 createApp（Vue 3）动态创建组件实例。
    • 返回 Promise，直接解析用户操作结果。

  • 代码片段：

    import { createApp } from 'vue'
import VueFinalModal from 'vue-final-modal'

const showModal = options => {
  return new Promise(resolve => {
    const modal = createApp({
      extends: VueFinalModal,
      propsData: options
    }).mount(document.createElement('div'))
    modal.$on('confirm', () => resolve('confirm'))
    modal.$on('cancel', () => resolve('cancel'))
  })

// 使用

  • 优点：

    • 轻量、无依赖。
    • 内置 Promise 支持，开箱即用。
    • 支持动态挂载，自销毁。

  • 缺点：

    • 配置稍复杂，需手动调整样式。

4. vuejs-dialog

  • 特点：

    • 一个专注于 Promise 的对话框库，支持 Vue 2。
    • 提供 this.$dialog.confirm 等便捷方法。

  • 实现思路：

改进思路与封装优化

基于你的需求（Vue 2/3 兼容、动态 props、异步状态返回、完美兼容），我从上述项目中提取灵感，提出以下改进思路和最佳封装方案：

改进思路

  1. Vue 2/3 兼容：
    • 使用 vue-demi 抹平 Vue 2 和 Vue 3 的 API 差异。
    • 统一使用 Composition API（如 setup），兼容 Options API。
  2. 动态 Props：
    • 通过对象式 props 传递配置（如 { title, content, confirmText }）。
    • 支持 slot 自定义内容。
  3. 异步状态返回：
    • 内置 Promise 支持，返回 confirm 或 cancel。
    • 提供工具函数（如 showDialog），简化调用。
  4. 完美兼容：
    • 使用动态挂载，避免组件状态依赖父组件。
    • 支持 SSR（服务端渲染）和客户端一致性。

最佳封装方案

结合 vue-final-modal 的动态挂载和 vuejs-dialog 的 Promise 风格，我推荐以下实现：

1. Dialog 组件 (Dialog.vue)

import { createApp, isVue2, Vue2 } from 'vue-demi'
import Dialog from './Dialog.vue'

export function showDialog(options = {}) {
  return new Promise(resolve => {
    const div = document.createElement('div')
    document.body.appendChild(div)

    const dialog = isVue2
      ? new (Vue2.extend(Dialog))({
          propsData: { ...options, visible: true }
        })
      : createApp({
          render: () =>
            h(Dialog, {
              ...options,
              visible: true,
              'onUpdate:visible': val => !val && cleanup(),
              onConfirm: () => resolve('confirm'),
              onCancel: () => resolve('cancel')
            })
        })

    const cleanup = () => {
      if (isVue2) {
        dialog.$destroy()
      } else {
        dialog.unmount()
      }
      div.remove()
    }

    if (isVue2) {
      dialog.$on('confirm', () => resolve('confirm'))
      dialog.$on('cancel', () => resolve('cancel'))
      dialog.$mount(div)
    } else {
      dialog.mount(div)
    }
  })
}

  3. 灵活性：
    • 通过 options 对象传递任意 props，支持动态配置。
    • 可扩展为支持 slot 或自定义组件。
  4. 性能：

  5. 对比开源项目：
