基本命令

以下是日常使用中最重要的命令：

命令 功能 示例
claude 启动交互模式 claude
claude "task" 运行一次性任务 claude "fix the build error"
claude -p "query" 运行一次性查询，然后退出 claude -p "explain this function"
claude -c 在当前目录中继续最近的对话 claude -c
claude -r 恢复之前的对话 claude -r
claude commit 创建 Git 提交 claude commit
/ 查看内置命令和技能 /
! Bash 模式, 执行 Bash 命令 !ls !git status !npm run build
/clear 清除对话历史 /clear
/btw 侧边快速提问 /btw 这个函数的返回值是什么类型
/help 或 ? 显示可用命令 /help
exit  或 两次Ctrl+C 退出 Claude Code 两次exit
Ctrl+C 或两次 ESC 取消当前输入或生成，标准中断 Ctrl+C
Ctrl+Enter 换行输出提示词 Ctrl+Enter
Ctrl+o 切换详细输出模式（显示更多思考过程或完整日志） Ctrl+o
Ctrl+l 清除终端屏幕，保留对话历史 Ctrl+C
Ctrl+t 切换/显示后台任务列表（background tasks） Ctrl+t
Alt+v 粘贴图像 Alt+v
Ctrl+R 反向搜索命令历史，交互式搜索先前命令 Ctrl+R
Ctrl+s 临时保存当前提示（stash），方便之后恢复 Ctrl+s
Ctrl+g 打开默认文本编辑器来编辑当前的长提示，特别适合写很长的复杂提示时，先用外部编辑器写好再粘贴回来令，避免在 CLI 中写长提示 Ctrl+g
Ctrl+Shift+- 于撤销上一步输入或编辑操作 Ctrl+Shift+-
Shift+Tab 循环切换权限模式，通过  default（每次编辑都询问你权限） 、 acceptEdits（自动接受文件编辑，无需每次确认，适合信任 Claude 时使用） 、 plan （先规划，再执行） Shift+Tab
Meta（Ctrl 或 Alt，取决于系统）+p 快速在 Claude Sonnet / Opus 等模型间切换 Alt+p

有关完整的命令列表，请参阅  CLI 参考、交互模式。

常见工作流程

使用 Claude Code 探索代码库、修复错误、重构、测试和其他日常任务的分步指南。

本页涵盖日常开发的实用工作流程：探索陌生代码、调试、重构、编写测试、创建 PR 和管理会话。每个部分都包含示例提示，您可以根据自己的项目进行调整。有关更高级的模式和提示，请参阅最佳实践。

1) 快速理解新代码库

步骤一：进入项目并启动

cd /path/to/project
claude

步骤二：先问全局，再问细节

请先给我这个代码库的整体概览

请解释这里使用的主要架构模式

关键的数据模型有哪些？

这个项目的认证流程是如何处理的？

步骤三：定位相关代码并追踪执行流程

请找出处理用户认证相关逻辑的文件

这些认证相关文件之间是如何协作的？

请从前端到数据库追踪一次登录流程

2) 高效修复错误

步骤一：先给可复现信息

  • 告诉 Claude 报错命令、堆栈和复现步骤（稳定复现/偶发都要说明）。
  • 如果有日志，直接粘贴或通过管道传入。
我在运行 npm test 时出现报错，请帮我定位原因

步骤二：先要修复思路，再执行改动

请给出几种修复 user.ts 中 @ts-ignore 的方案

请按你建议的方案修改 user.ts，并补上空值判断

3) 安全重构代码

推荐节奏：小步重构 + 每步验证

请找出代码库里已废弃 API 的使用位置

请建议如何重构 utils.js，使用更现代的 JavaScript 写法

请在保持行为一致的前提下，用 ES2024 特性重构 utils.js

请运行重构后的相关测试并反馈结果

4) 使用 Plan Mode 做安全分析

适用场景：改动范围大、需要先评估方案、涉及多个模块联动。

启用方式

  • 会话中按 Shift+Tab 切换到 Plan Mode。
  • 或启动时直接使用：
claude --permission-mode plan
claude --permission-mode plan -p "请分析当前认证系统并给出改进建议"

典型用法

我需要把现有认证系统重构为 OAuth2，请给出详细迁移方案

向后兼容方面需要怎么处理？

数据库迁移应该如何规划和执行？

5) 补测试与边界覆盖

建议流程

请找出 NotificationsService.swift 中尚未被测试覆盖的函数

请为通知服务补充测试

请补充通知服务在边界条件下的测试用例

请运行新增测试并修复失败项

要点：明确“要验证什么”，让 Claude 重点覆盖边界值、异常路径和易漏场景。

6) 创建 PR（拉取请求）

请总结我在认证模块上的改动

请为当前改动创建一个 PR

请补充 PR 描述，重点说明这次安全改进的背景与价值

建议在提交前让 Claude 额外检查风险点、回归影响和测试说明。

7) 文档补全与规范化

建议流程

识别未记录的代码

请找出 auth 模块中缺少规范 JSDoc 注释的函数

生成文档

请为 auth.js 中未文档化的函数补充 JSDoc 注释

审查和增强

请优化生成的文档，补充更多上下文和示例

验证文档

请检查文档是否符合我们的项目规范

使用图像

当文字描述不够直观时，可直接让 Claude 基于图片理解问题并给出建议。

建议流程

将图片加入对话

  • 直接拖拽图片到对话窗口。
  • 或复制图片后粘贴到 CLI（Windows/Linux 常用 Ctrl+V）。
  • 或提供图片路径。

让 Claude 分析图片内容

这张图里展示了什么？

请描述这张截图中的 UI 元素和层级关系

请检查这张图里是否有明显的设计或交互问题

结合图片排查问题或生成代码建议

这是报错截图，请帮我判断可能的根因

这是当前数据库结构图，请给出支持新功能的调整建议

请根据这张设计图生成对应的 CSS 结构

要点：涉及 UI、报错现场、流程图时，优先附图，信息密度更高、沟通成本更低。

引用文件和目录

使用 @ 引用文件或目录，可显著减少“描述不清文件位置”带来的沟通损耗。

建议流程

引用单个文件

请解释 @src/utils/auth.js 的核心逻辑

引用目录结构

请说明 @src/components 的目录结构和职责划分

引用 MCP 资源（如已接入）

请展示 @github:repos/owner/repo/issues 的数据

使用建议

  • 优先用 @ 指定上下文，避免让 Claude 猜文件位置。
  • 可在同一条消息中引用多个文件，便于跨文件分析。
  • 引用目录时会给出文件列表，适合先做范围收敛再深入。

8) 管理会话与恢复上下文

常用命令

claude --continue
claude --resume
claude --from-pr 123

实践建议

  • 处理多个任务时尽早给会话命名，便于后续恢复。
  • 任务切换频繁时，善用会话恢复，避免反复补充背景信息。

9) 并行任务：使用 Git worktree

当需要并行处理多个需求（如新功能 + 紧急修复）时，建议为每个任务创建独立 worktree，减少改动互相干扰。

claude --worktree feature-auth
claude --worktree bugfix-123

或手动管理：

git worktree add ../project-feature-a -b feature-a
git worktree add ../project-bugfix bugfix-123
git worktree list
git worktree remove ../project-feature-a

10) 把 Claude 当作命令行工具集成

作为审查/校验步骤

"scripts": {
  "lint:claude": "claude -p '你现在充当代码校验器。请检查当前改动与 main 分支的差异，报告所有拼写相关问题。每个问题分两行输出：第一行写文件名和行号，第二行写问题描述。除这些内容外不要输出其他文本。'"
}

管道输入输出

cat build-error.txt | claude -p "请简要说明这次构建报错的根因" > output.txt

指定输出格式

  • text：纯文本，适合直接阅读
  • json：结构化输出，适合脚本集成
  • stream-json：流式输出，适合实时处理
claude -p "请总结这份数据的关键信息" --output-format text
claude -p "请分析这段代码中的潜在缺陷" --output-format json
claude -p "请解析这份日志并提取错误信息" --output-format stream-json

Claude Code 最佳实践

https://code.claude.com/docs/zh-CN/best-practices

给 Claude 一种验证其工作的方式

包括测试、屏幕截图或预期输出，以便 Claude 可以检查自己。这是你能做的最高杠杆的事情。

当 Claude 能够验证自己的工作时，例如运行测试、比较屏幕截图和验证输出，它的表现会显著提高。

先探索，再规划，最后编码

将研究和规划与实现分开，以避免解决错误的问题。

让 Claude 直接跳到编码可能会产生解决错误问题的代码。使用  Plan Mode  将探索与执行分开。

在提示中提供具体的上下文

你的指令越精确，你需要的更正就越少。

Claude 可以推断意图，但它不能读心术。引用特定文件、提及约束，并指出示例模式。

提供丰富的内容

使用 @ 引用文件、粘贴屏幕截图/图像或直接管道数据。

  • 使用  @  引用文件，而不是描述代码的位置。Claude 在响应前读取文件。
  • 直接粘贴图像。复制/粘贴或拖放图像到提示中。
  • 提供 URL  用于文档和 API 参考。使用  /permissions  来允许列表经常使用的域。
  • 管道数据  通过运行  cat error.log | claude  直接发送文件内容。
  • 让 Claude 获取它需要的东西。告诉 Claude 使用 Bash 命令、MCP 工具或通过读取文件来自己拉取上下文。

配置你的环境

一些设置步骤使 Claude Code 在所有会话中显著更有效。有关扩展功能的完整概述和何时使用每个功能，请参阅  扩展 Claude Code。

编写有效的 CLAUDE.md

运行 /init 根据你的当前项目结构生成启动 CLAUDE.md 文件，然后随时间精化。

CLAUDE.md 文件没有必需的格式，但保持简短和易读。

CLAUDE.md 在每个会话中加载，所以只包括广泛适用的东西。对于仅有时相关的域知识或工作流，改用  skills。Claude 按需加载它们，不会使每次对话都膨胀。

保持简洁。对于每一行，问自己："删除这个会导致 Claude 犯错吗？"  如果不会，删除它。膨胀的 CLAUDE.md 文件会导致 Claude 忽略你的实际指令！

使用 CLI 工具

告诉 Claude Code 在与外部服务交互时使用 CLI 工具，如  gh、aws、gcloud  和  sentry-cli。

连接 MCP 服务器

运行 claude mcp add 来连接外部工具，如 Notion、Figma 或你的数据库。

使用  MCP servers，你可以要求 Claude 从问题跟踪器实现功能、查询数据库、分析监控数据、集成来自 Figma 的设计并自动化工作流。

设置 hooks

使用 hooks 来处理必须每次发生且没有例外的操作。

Hooks  在 Claude 工作流中的特定点自动运行脚本。与 CLAUDE.md 指令不同，hooks 是确定性的，保证操作发生。

创建 skills

在  .claude/skills/  中创建  SKILL.md  文件，为 Claude 提供域知识和可重用工作流。

Skills  使用特定于你的项目、团队或域的信息扩展 Claude 的知识。Claude 在相关时自动应用它们，或者你可以使用  /skill-name  直接调用它们。

通过向  .claude/skills/  添加带有  SKILL.md  的目录来创建 skill：

.claude/skills/api-conventions/SKILL.md

---
name: api-conventions
description: REST API design conventions for our services
---

# API Conventions

- Use kebab-case for URL paths
- Use camelCase for JSON properties
- Always include pagination for list endpoints
- Version APIs in the URL path (/v1/, /v2/)

安装 plugins

运行 /plugin 来浏览市场。Plugins 添加 skills、工具和集成，无需配置。

Plugins  将 skills、hooks、subagents 和 MCP 服务器捆绑到来自社区和 Anthropic 的单个可安装单元中。如果你使用类型化语言，安装  代码智能 plugin  来为 Claude 提供精确的符号导航和编辑后的自动错误检测。

有关在 skills、subagents、hooks 和 MCP 之间选择的指导，请参阅  扩展 Claude Code。

有效沟通

你与 Claude Code 沟通的方式显著影响结果的质量。

提出代码库问题

问 Claude 你会问资深工程师的问题。

让 Claude 采访你

对于更大的功能，让 Claude 先采访你。从最小的提示开始，要求 Claude 使用 AskUserQuestion 工具采访你。

管理你的会话

对话是持久的和可逆的。利用这一点！

尽早且经常改正方向

一旦你注意到 Claude 偏离轨道，立即改正它。

最好的结果来自紧密的反馈循环。虽然 Claude 有时会在第一次尝试时完美地解决问题，但快速改正它通常会更快地产生更好的解决方案。

  • Esc：使用  Esc  键在中途停止 Claude。Context 被保留，所以你可以重定向。
  • Esc + Esc  或  /rewind：按  Esc  两次或运行  /rewind  来打开 rewind 菜单并恢复之前的对话和代码状态，或从选定的消息进行总结。
  • "撤销那个"：让 Claude 恢复其更改。
  • /clear：在不相关的任务之间重置 context。长会话与无关的 context 可能会降低性能。

如果你在一个会话中对同一问题改正了 Claude 两次以上，context 就充满了失败的方法。运行  /clear  并使用更具体的提示重新开始，该提示包含你学到的东西。干净的会话与更好的提示几乎总是优于长会话与累积的改正。

积极管理 context

在不相关的任务之间频繁运行 /clear 来重置 context。

使用 subagents 进行调查

使用  "use subagents to investigate X"  委托研究。它们在单独的 context 中探索，为实现保持你的主对话干净。

由于 context 是你的基本约束，subagents 是可用的最强大的工具之一。当 Claude 研究代码库时，它读取许多文件，所有这些都消耗你的 context。Subagents 在单独的 context windows 中运行并报告摘要。

subagent 探索代码库、读取相关文件并报告发现，所有这些都不会使你的主对话混乱。

恢复对话

运行 claude --continue 来继续你离开的地方，或 --resume 来从最近的会话中选择。

避免常见失败模式

这些是常见的错误。尽早识别它们可以节省时间：

  • 厨房水槽会话。  你从一个任务开始，然后问 Claude 一些不相关的东西，然后回到第一个任务。Context 充满了无关的信息。

    修复：在不相关的任务之间  /clear。

  • 一次又一次地改正。 Claude 做错了什么，你改正它，它仍然是错的，你再改正。Context 被失败的方法污染。

    修复：在两次失败的改正后，/clear  并编写一个更好的初始提示，包含你学到的东西。

  • 过度指定的 CLAUDE.md。  如果你的 CLAUDE.md 太长，Claude 会忽略一半，因为重要的规则在噪音中丢失。

    修复：无情地修剪。如果 Claude 已经在没有指令的情况下正确地做某事，删除它或将其转换为 hook。

  • 信任然后验证的差距。 Claude 产生一个看起来合理的实现，但不处理边界情况。

    修复：始终提供验证（测试、脚本、屏幕截图）。如果你不能验证它，不要发布它。

  • 无限探索。  你要求 Claude "调查"某些东西而不限定范围。Claude 读取数百个文件，填充 context。

    修复：狭隘地限定调查或使用 subagents，以便探索不会消耗你的主 context。

培养你的直觉

本指南中的模式不是一成不变的。它们是通常效果很好的起点，但可能不是每种情况的最优选择。

有时你应该让 context 累积，因为你深入一个复杂的问题，历史很有价值。有时你应该跳过规划，让 Claude 弄清楚，因为任务是探索性的。有时模糊的提示正是你想要的，因为你想看看 Claude 如何解释问题，然后再限制它。

注意什么有效。当 Claude 产生很好的输出时，注意你做了什么：提示结构、你提供的 context、你所在的模式。当 Claude 遇到困难时，问为什么。Context 太嘈杂了吗？提示太模糊了吗？任务对于一次通过来说太大了吗？

随着时间的推移，你会培养没有指南能捕捉的直觉。你会知道何时具体，何时开放，何时规划，何时探索，何时清除 context，何时让它累积。

扩展 Claude Code

https://code.claude.com/docs/zh-CN/features-overview

概述

  • CLAUDE.md  添加 Claude 每个会话都能看到的持久上下文
  • Skills  添加可重用的知识和可调用的工作流
  • MCP  将 Claude 连接到外部服务和工具
  • Subagents  在隔离的上下文中运行自己的循环，返回摘要
  • Agent teams  协调多个独立会话，具有共享任务和点对点消息传递
  • Hooks  完全在循环外作为确定性脚本运行
  • Plugins  和  marketplaces  打包和分发这些功能

Skills  是最灵活的扩展。Skill 是一个包含知识、工作流或说明的 markdown 文件。您可以使用  /deploy  之类的命令调用 skills，或者 Claude 可以在相关时自动加载它们。Skills 可以在您当前的对话中运行，也可以通过 subagents 在隔离的上下文中运行。

将功能与您的目标相匹配

功能范围从 Claude 每个会话都能看到的始终开启的上下文，到您或 Claude 可以调用的按需功能，再到在特定事件上运行的后台自动化。下表显示了可用的功能以及何时使用每个功能。

功能 作用 何时使用 示例
CLAUDE.md 每次对话加载的持久上下文 项目约定、"始终执行 X" 规则 "使用 pnpm，而不是 npm。提交前运行测试。"
Skill Claude 可以使用的说明、知识和工作流 可重用内容、参考文档、可重复的任务 /deploy  运行您的部署清单；包含端点模式的 API 文档 skill
Subagent 返回摘要结果的隔离执行上下文 上下文隔离、并行任务、专门的工作者 读取许多文件但仅返回关键发现的研究任务
Agent teams 协调多个独立的 Claude Code 会话 并行研究、新功能开发、使用竞争假设进行调试 生成审查者同时检查安全性、性能和测试
MCP 连接到外部服务 外部数据或操作 查询您的数据库、发布到 Slack、控制浏览器
Hook 在事件上运行的确定性脚本 可预测的自动化，不涉及 LLM 每次文件编辑后运行 ESLint

Plugins  是打包层。Plugin 将 skills、hooks、subagents 和 MCP servers 捆绑到单个可安装单元中。Plugin skills 是命名空间的（如  /my-plugin:review），因此多个 plugins 可以共存。当您想在多个存储库中重用相同的设置或通过  marketplace  分发给他人时，使用 plugins。
